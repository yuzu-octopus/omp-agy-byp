## Angle
Angle F4 — Rate/usage anomaly detection, risk scoring, account bans, telemetry. Question: How do vendors detect anomalous usage and enforce account bans / risk scoring on consumer subscriptions, and what does Google document? Scope: consumer Gemini app / Google AI Pro / Ultra vs developer Gemini API / Google Cloud. Cover per-account vs per-key quotas, usage-limit signals, telemetry events, escalation throttling→ban. Google documents quota mechanics and Cloud-side abuse monitoring extensively; it does NOT document consumer-side risk-scoring internals. `[inference]` marks every extrapolation, paired with a documented analogous mechanism. Research neutral/technical; ToS material reported as documented enforcement mechanism, not as legal veto. No exploit code.

## Claims

### A. Quota unit: per-key vs per-account/per-project
1. Gemini API rate limits are applied **per project, not per API key**; multiple keys in one project share the same limit. Configured limits are evaluated on each dimension (RPM, TPM, RPD, etc.); exceeding any one triggers a rate-limit error. — https://ai.google.dev/gemini-api/docs/rate-limits — fetched 2026-11-18 — primary
2. Gemini API RPD quotas reset at midnight Pacific time; limits vary per model; experimental/preview models get stricter limits. Spend-based limits use a rolling 10-minute window and depend on billing history and "account standing." Values: Tier 1 $10, Tier 2 $50, Tier 3 $200 per 10 minutes; breach returns `429 RESOURCE_EXHAUSTED`. — https://ai.google.dev/gemini-api/docs/rate-limits — fetched 2026-11-18 — primary
3. Gemini API usage tiers are project-tied and auto-upgrade with spend; Tier 2 requires $100 + 3 days from first successful payment, Tier 3 $1,000 + 30 days, based on cumulative spend of the linked billing account. Upgrade "may be denied based on other factors identified during the review process" (factors unspecified). — https://ai.google.dev/gemini-api/docs/rate-limits — fetched 2026-11-18 — primary
4. Cloud Quotas: quotas generally apply at the **Google Cloud project level**; use in one project does not affect another; **within a project, quotas are shared across all applications and IP addresses**; when consumption exceeds quota the system blocks access and the task fails. — https://cloud.google.com/docs/quotas/quotas — fetched 2026-11-18 — primary
5. Same project-level/shared-across-apps-and-IP rule restated in Cloud IDS quota docs; quotas monitor consumption, restrict it, and block over-quota access. — https://cloud.google.com/intrusion-detection-system/quotas — fetched 2026-11-18 — primary
6. Consumer Gemini app limits are **plan-tier keyed, not key keyed**: without AI plan = standard; AI Plus = 2x standard; AI Pro = 4x; AI Ultra = 5x or 20x AI Pro. Advanced models and higher thinking levels consume more of the usage; media generation and Deep Research consume more. — https://support.google.com/gemini/answer/16275805?hl=en — fetched 2026-11-18 — primary
7. Work/school Gemini app limits are **per-user-license** and tiered: Pro "up to 25 prompts per 4 hours," "up to 200 prompts/day," "up to 500 prompts/day" by license; Thinking "up to 300 / 600 / 1500 prompts/day"; Deep Research "5 reports/month" to "120 reports/day." Basic access "varies; daily limits may change frequently." — https://support.google.com/gemini/answer/14620100?hl=en — fetched 2026-11-18 — primary
8. Workspace Terms define Gemini Business/Education/Education Premium/Ultra-for-Business as "subject to the usage limits allocated per End User license" (as may be updated from time to time). — https://workspace.google.com/terms/user_features — fetched 2026-11-18 — primary
9. First-party Gemini CLI FAQ: `API error: 429 - Resource exhausted` = exceeded API request limit; "rate limits to prevent abuse and ensure fair usage"; remedies: check usage in AI Studio / Cloud dashboard, batch/delay prompts, request quota increase. — https://google-gemini.github.io/gemini-cli/docs/faq.html — fetched 2026-11-18 — primary

### B. Usage-limit signals (user-visible)
10. Gemini Apps notify the user when close to the limit based on plan level; a second notification on reaching the limit states when it refreshes; an in-app "Usage" view exists. — https://support.google.com/gemini/answer/16275805?hl=en — fetched 2026-11-18 — primary
11. Limits "may change without notice, including due to capacity constraints"; on large activity increases Google may change limits "to maintain a high standard of quality." — https://support.google.com/gemini/answer/16275805?hl=en — fetched 2026-11-18 — primary
12. Number of prompts before limit varies with prompt length/complexity, size and number of uploaded files, and conversation length; capacity replenishes regularly; on hitting Thinking/Pro limit the user can continue with Fast in the same chat. — https://support.google.com/gemini/answer/14620100?hl=en — fetched 2026-11-18 — primary
13. Practitioner reports (first-hand, not vendor docs): "Upgrade for higher limits" message, countdown-style "limited until <time>", silent automatic switch from 2.5 Pro to 2.5 Flash after hitting the Pro cap, and "up to" figures described as dynamic ceilings varying with system load; free-tier users reportedly hit adjustments before paid users. Absolute Pro figure repeatedly reported as ~100 prompts/day — **unverified** (no official absolute number found). — https://support.google.com/gemini/thread/417542222/inquiry-regarding-daily-request-limits-for-google-ai-pro-subscription?hl=en — fetched 2026-11-18 — practitioner report
14. Practitioner reports (first-hand, not vendor docs): Gemini CLI 429 `RESOURCE_EXHAUSTED` with `reason: rateLimitExceeded`, and `MODEL_CAPACITY_EXHAUSTED` with message "No capacity available for model … on the server" on `cloudcode-pa.googleapis.com`; some paid `g1-pro-tier` responses lacked a `Retry-After` header; trace IDs and client user-agent captured. — https://github.com/google-gemini/gemini-cli/issues/22648 and https://github.com/google-gemini/gemini-cli/issues/24004 — fetched 2026-11-18 — practitioner report
15. Practitioner report (first-hand, not vendor docs): paid subscribers reported immediate 429s after full local reset on Gemini CLI, while AI Studio web worked with the same account; issue labelled by maintainers `area/platformIssues … Capacity, Quota mgmt`. — https://github.com/google-gemini/gemini-cli/issues/22545 — fetched 2026-11-18 — practitioner report

### C. Telemetry / anomaly detection (documented)
16. Service Specific Terms §4: "Google uses automated safety tools to detect abuse of Generative AI Services"; if tools detect potential abuse or AUP/Prohibited Use Policy violation, Google "may log prompts made by Partner or a Non-TOS Customer solely for the purpose of reviewing and determining whether a violation has occurred." — https://cloud.google.com/terms/service-terms — fetched 2026-11-18 — primary
17. Abuse monitoring docs: automated detection via **safety classifiers**; all prompts/responses on covered Advanced AI models logged and stored up to 30 days; if classifiers detect suspicious activity, prompts logged up to **90 days** for human review; processing includes "anonymized shingles and analyze usage patterns"; data not used to train models; abuse logs not CMEK-encrypted; customers under a Google Cloud Master Agreement exempt from human review by default. — https://cloud.google.com/vertex-ai/generative-ai/docs/learn/abuse-monitoring — fetched 2026-11-18 — primary
18. Abuse monitoring escalation endpoints: authorized Google employees may assess flagged prompts and contact the customer; "Failure to address the behavior—or recurring or severe abuse—may result in suspension or termination of the customer's access to Gemini Enterprise Agent Platform or Google Cloud services." — https://cloud.google.com/vertex-ai/generative-ai/docs/learn/abuse-monitoring — fetched 2026-11-18 — primary
19. Customer-facing quota telemetry: Cloud Monitoring exposes `serviceruntime.googleapis.com/quota/allocation/usage`, `quota/limit`, and `/quota/exceeded` on monitored resource `consumer_quota`, grouped by `project_id`, `quota_metric`, `location`; documented PromQL example alerts when usage/limit > 0.8. This is operator-visible quota observability, not a Google risk score. — https://cloud.google.com/monitoring/alerts/using-quota-metrics — fetched 2026-11-18 — primary
20. reCAPTCHA Enterprise score: decimal **0.0–1.0**, 11 levels, 1.0 = low risk/likely legitimate, 0.0 = high risk/might be fraudulent; only four levels (0.1, 0.3, 0.7, 0.9) available before an **automatic security review** triggered by adding a billing account; reason codes available after that review; recommended actions include requiring MFA/email verification on low login scores, limiting abusive users, sending risky comments to moderation. — https://cloud.google.com/recaptcha-enterprise/docs/interpret-assessment-website — fetched 2026-11-18 — primary
21. Vendor blog: reCAPTCHA Enterprise scores logins/signups/gift-card redemption/checkout; Cloud Armor can block or serve a CAPTCHA challenge to requests judged bot-like; **Account Defender** builds site-specific models to detect "a trend of suspicious behavior or a change in activity" over time. — https://cloud.google.com/blog/products/identity-security/bot-management-with-google-cloud — fetched 2026-11-18 — primary
22. Google Account security signals documented: alerts on important actions (new-device sign-in), suspicious activity (unusual number of emails sent), and blocked sensitive actions (checking stored passwords); delivered by phone/email; reviewable in "Recent security activity." — https://support.google.com/accounts/answer/2590353?hl=en — fetched 2026-11-18 — primary
23. Google Account unusual-activity channels: notification of unusual sign-in/new device, suspected username/password/security-setting change, other unrecognized activity, a red bar "We've detected suspicious activity in your account," and the Recent security activity page. — https://support.google.com/accounts/answer/140921?hl=en — fetched 2026-11-18 — primary
24. At-risk sign-in methods: if Google detects a suspicious sign-in method its use is restricted, an alert is sent, and if unverified it is automatically removed after 30 days; re-enable requires a trusted passkey/security key. — https://support.google.com/accounts/answer/17137073?hl=en — fetched 2026-11-18 — primary
25. "Suspicious sign in prevented" email = Google blocked an access attempt because it was unsure it was the user, e.g. sign-in from a different location/device than normal. — https://support.google.com/accounts/answer/6063333?hl=en — fetched 2026-11-18 — primary

### D. Escalation throttling → ban (documented mechanisms)
26. Cloud ToS §4.1: on AUP violation Google notifies and requests correction; failure to correct within **24 hours** → Google may suspend all or part of use until corrected. — https://cloud.google.com/terms — fetched 2026-11-18 — primary
27. Cloud ToS §4.2: immediate suspension permitted if use could adversely impact services/other customers/network, suspected unauthorized third-party access, legal compulsion, or breach of §3.3 restrictions; Google lifts suspension when circumstances resolved and, on request, notifies basis. — https://cloud.google.com/terms — fetched 2026-11-18 — primary
28. Cloud ToS §3.3 restrictions prohibit using services "in a manner intended to avoid incurring Fees (including creating multiple Customer Applications, Accounts, or Projects to simulate or act as a single …) or to circumvent Service-specific usage limits or quotas." Documented enforcement rule; reported neutrally, not as a legal gate. — https://cloud.google.com/terms/index-20230206 — fetched 2026-11-18 — primary
29. Service Specific Terms: "Google may immediately suspend or terminate Customer's use of a Generative AI Service based on any suspected violation"; separate AI/ML competitive-use clause also permits immediate suspend/terminate on suspicion. — https://cloud.google.com/terms/service-terms — fetched 2026-11-18 — primary
30. Consumer account ban path: "Your account is disabled" — user selects Start Appeal; if appeal not approved the entire account remains unavailable and, absent further action, is permanently disabled and considered for deletion; for some policy violations Google reviews **up to 2 appeals**, then closes further ones. — https://support.google.com/accounts/answer/40695?hl=en — fetched 2026-11-18 — primary
31. Practitioner report (first-hand, not vendor docs): new Google One AI Premium account created Dec 24 2025, after generating a Gemini API key for Gemini CLI the account was flagged/suspended from Google Cloud/Developer services, three appeals unanswered for 40+ days, phone support said it cannot lift Cloud suspensions; author attributes to automated "bot" flag on a brand-new account — **unverified cause**. — https://support.google.com/googleone/thread/406695374/legitimate-account-suspended-google-one-gemini-api-40-days-no-response?hl=en — fetched 2026-11-18 — practitioner report
32. Practitioner report (first-hand, not vendor docs): repeated automatic disablement with message that account "may have been created or used by a bot," appeal → restore → disable again after days; user reports no way to identify triggering activity/device/IP; Google One support said it cannot view/override disabled-account appeal decisions. — https://support.google.com/accounts/thread/470714570/my-google-account-keeps-getting-automatically-disabled-bot-account-block?hl=en and https://support.google.com/accounts/thread/461760216/google-account-wrongly-disabled-for-%E2%80%9Cmultiple-accounts-bot%E2%80%9D-activity?hl=en — fetched 2026-11-18 — practitioner report
33. Practitioner report (first-hand, not vendor docs): paid subscriber reported 429 loop where AI Studio API key limits showed "limit: 0"; workaround reported as deleting API keys so CLI authenticates via subscription OAuth, or manually linking a billing account. — https://github.com/google-gemini/gemini-cli/issues/24396 — fetched 2026-11-18 — practitioner report

## Conflicting evidence
- Consumer plan limits: official docs give only relative multipliers ("4x standard", "5x or 20x AI Pro") and Workspace "up to N prompts" tables; community repeatedly asserts ~100 prompts/day for Pro — **unverified**, no official absolute number located.
- Gemini CLI: "Unlimited coding assistant" / `g1-pro-tier` entitlement advertised vs practitioner 429 `RESOURCE_EXHAUSTED` on the same tier. Cause disputed (capacity, misconfigured entitlement, or quota routing) — no vendor statement.
- Suspension timing: Cloud ToS §4.1 gives a 24-hour cure window; Service Specific Terms permit immediate suspend/terminate on **suspected** Gen-AI violation; abuse-monitoring doc gives classifier → human contact → suspension. Different regimes, unreconciled for consumer plans.
- Framing conflict: Gemini app docs describe "prompts per day" caps, while the same docs say advanced models/higher thinking/large files consume more usage — implies a usage-weighted budget, not a pure message count; no public formula published.
- reCAPTCHA: 11 score levels documented, but only 4 available until billing-based automatic security review — tiered access to granularity, not a single score regime.
- Account bans: practitioner reports attribute suspensions to "bot"/"multiple accounts" flags; Google's public disabled-account page lists no reason taxonomy — cause unverified.
- Practitioner reports of "limit: 0" on paid AI Studio keys vs official tier table (Tier 1+ nonzero) — inconsistent, likely entitlement propagation bug per reports; unverified.

## Gaps
- No official doc enumerating consumer Gemini app anomaly-detection signals, risk-score inputs, or thresholds.
- No doc linking Cloud/Vertex abuse classifiers to **consumer subscription** suspension (only to Cloud / Gemini Enterprise Agent Platform access).
- No published definition of "account standing" used in Gemini API spend-limit gating; no criteria for denied tier upgrades.
- No published escalation matrix (warning → throttle → suspend → permanent ban) for consumer AI plans; appeals documented, trigger taxonomy not.
- No official absolute numeric limit for Gemini AI Pro in the app; only multipliers and "up to" figures for Workspace SKUs.
- No evidence in docs that reCAPTCHA Enterprise assessments are used on Gemini app endpoints (`[inference]` only).
- No vendor confirmation of practitioner claims: bot-flag suspensions, 100→25 prompt drops, "limit: 0" paid keys, missing `Retry-After`.
- Telemetry events named publicly are quota metrics (`quota/allocation/usage`, `quota/limit`, `quota/exceeded`) and abuse logs; no event schema for consumer-side anomaly scoring published.
