## Angle

F3 — Client-fingerprinting detection class. Question: which TLS/JA3/JA4, HTTP/2, HTTP-header, device-attestation and browser-fingerprinting techniques are documented as bot/abuse signals by primary sources, and which are plausibly or actually used by Google against consumer-subscription (Gemini app / AI Pro / Ultra) traffic. Scope is neutral technical survey; no exploit code, no legal gate. Google-internal behavior is labeled `[inference]` where derived from shipped Google code/infrastructure rather than documented policy.

## Claims

**TLS / JA3 / JA4**

- JA3 hashes the cleartext TLS ClientHello fields `SSLVersion,Cipher,SSLExtension,EllipticCurve,EllipticCurvePointFormat` with MD5 into a 32-char hash; GREASE values are ignored, and the fingerprint stays stable across destination IPs, ports and certificates. — https://raw.githubusercontent.com/salesforce/ja3/master/README.md (fetched 2026-11-18) — confidence: primary (spec repo).
- JA4 encodes transport (q/d/t), TLS version, SNI presence, cipher count, extension count and ALPN, then truncated SHA-256 hashes of sorted ciphers and sorted extensions + signature algorithms; sorting extensions makes it stable under Chrome's randomized extension order. — https://raw.githubusercontent.com/FoxIO-LLC/ja4/main/technical_details/JA4.md ; https://foxio.io/blog/ja4-network-fingerprinting (fetched 2026-11-18) — confidence: primary (spec repo + author's blog).
- JA4+ is a suite spanning TLS client (JA4), TLS server (JA4S), HTTP client (JA4H), TCP (JA4T), X509 (JA4X), latency (JA4L), SSH, DHCP; stated uses include bot detection, session-hijacking prevention and malware detection. — https://raw.githubusercontent.com/FoxIO-LLC/ja4/main/technical_details/README.md ; https://foxio.io/blog/ja4-network-fingerprinting (fetched 2026-11-18) — confidence: primary (spec repo).
- **Google edge computes JA3 and JA4**: Google Cloud global external Application Load Balancer exposes custom-header variables `tls_ja3_fingerprint` and `tls_ja4_fingerprint` (plus `tls_version`, `tls_cipher_suite`, `tls_sni_hostname`, `client_protocol`, `client_rtt_msec`, `device_request_type`, `user_agent_family`, ASN). — https://docs.cloud.google.com/load-balancing/docs/https/custom-headers-global.md.txt (fetched 2026-11-18) — confidence: primary (Google docs).
- **Google Cloud Armor rule language exposes `origin.tls_ja3_fingerprint` and `origin.tls_ja4_fingerprint`** as match attributes for allow/deny/rate-limit decisions, alongside `request.headers`, `origin.asn`, `origin.region_code`. — https://docs.cloud.google.com/armor/docs/rules-language-reference.md.txt (fetched 2026-11-18) — confidence: primary (Google docs).
- Cloudflare enterprise Bot Management surfaces `cf.bot_management.ja3_hash` / `ja4` for WAF rules, documents that JA3/JA4 can be absent on non-TLS traffic, Worker-routed requests and TLS session resumption, and uses them to allow mobile-app traffic or block attacks. — https://developers.cloudflare.com/bots/additional-configurations/ja3-ja4-fingerprint/index.md ; https://developers.cloudflare.com/bots/reference/bot-management-variables/index.md (fetched 2026-11-18) — confidence: primary (vendor docs).
- Cloudflare "Signals Intelligence" publishes per-JA4 aggregate features usable as ML inputs: `h2h3_ratio_1h`, `heuristic_ratio_1h`, `browser_ratio_1h`, known-bot ratio, distinct-UA/path/IP ranks and quantiles, cache ratio. — https://developers.cloudflare.com/bots/additional-configurations/ja3-ja4-fingerprint/signals-intelligence/index.md (fetched 2026-11-18) — confidence: primary (vendor docs).
- Akamai offers JA4 client TLS fingerprinting (beta) to "detect and mitigate bots", mitigate DDoS and block known attackers, injecting the fingerprint into a configurable HTTP header. — https://techdocs.akamai.com/application-security/reference/get-ja4-fingerprint-settings (fetched 2026-11-18) — confidence: primary (vendor docs).
- OWASP Bot Management Cheat Sheet recommends edge-layer TLS fingerprint (JA3/JA4) + HTTP/2 fingerprint, then application-layer signals; it warns against long raw-fingerprint retention and against blocking hardened browsers. — https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html (fetched 2026-11-18) — confidence: primary (industry guidance).
- Academic: CatBoost trained on JA4DB (227,404 records) classified bot vs benign at AUC 0.998 / F1 0.9734; top features `ja4_b`, cipher count, extension count. Same paper states TLS fingerprinting gives Low/None protection against full-stack browser emulation and Medium against advanced TLS spoofing. — https://arxiv.org/html/2602.09606 (fetched 2026-11-18) — confidence: primary (academic paper).
- Google-authored WWW 2024 paper measured Web-API-based browser fingerprinting telemetry from tens of millions of Chrome clients on 100,000+ websites over 5,383 surfaces from 161 Web APIs, including canvas readback, WebGL parameters, fonts, screen and user-agent surfaces; it treats fingerprinting as a privacy risk and anti-fraud/abuse capability. — https://arxiv.org/html/2403.15607 (fetched 2026-11-18) — confidence: primary (academic paper, Google authors). `[inference]` Google therefore has in-house capability to evaluate browser fingerprints; no evidence here of Gemini subscription enforcement.

**HTTP/2 and header ordering**

- Akamai's HTTP/2 passive fingerprint (>10M edge connections) uses SETTINGS parameter values *and order*, WINDOW_UPDATE increment, PRIORITY frame stream IDs/exclusivity/dependency/weight, and request pseudo-header order; proposed format `S[;]|WU|P[,]#|PS[,]`. — https://blackhat.com/docs/eu-17/materials/eu-17-Shuster-Passive-Fingerprinting-Of-HTTP2-Clients-wp.pdf (fetched 2026-11-18) — confidence: primary (vendor research paper).
- RFC 7540 §10.8 itself notes passive fingerprinting via SETTINGS values, flow-control-window management, stream priority allocation and reaction timing. — https://blackhat.com/docs/eu-17/materials/eu-17-Shuster-Passive-Fingerprinting-Of-HTTP2-Clients-wp.pdf (quotes RFC 7540) (fetched 2026-11-18) — confidence: primary (spec text as quoted in vendor paper).
- Akamai's corpus shows Chrome pseudo-header order `:method,:authority,:scheme,:path`, Firefox `:method,:path,:authority,:scheme`; Chrome/Windows and Chrome/macOS share identical H2 fingerprints, so OS is not separated by this signal. — https://blackhat.com/docs/eu-17/materials/eu-17-Shuster-Passive-Fingerprinting-Of-HTTP2-Clients-wp.pdf (fetched 2026-11-18) — confidence: primary (vendor research paper).
- Google Cloud Armor/Cloud Load Balancing expose `client_protocol` (`HTTP/1.0`, `HTTP/1.1`, `HTTP/2`, `HTTP/3`) and `tls_ja3_fingerprint` / `tls_ja4_fingerprint` for HTTPS, HTTP/2 and HTTP/3 connections — i.e., Google's edge can join protocol choice to TLS fingerprint. — https://docs.cloud.google.com/load-balancing/docs/https/custom-headers-global.md.txt (fetched 2026-11-18) — confidence: primary (Google docs). `[inference]` use against Gemini app traffic is plausible but undocumented.
- JA4H fingerprints each HTTP request; `JA4H_ab` is an application/method fingerprint where absence of `Accept-Language` is presented as a bot indicator; `JA4H_c` fingerprints cookie shape and `JA4H_d` can track a user. The spec file currently documents only the header-count field. — https://raw.githubusercontent.com/FoxIO-LLC/ja4/main/technical_details/JA4H.md ; https://foxio.io/blog/ja4-network-fingerprinting (fetched 2026-11-18) — confidence: primary (spec + author's blog).
- Academic (2026) multi-layer agent attribution measured six AI web agents including a Gemini computer-use agent on an instrumented site: features include JA3/JA4, Akamai H2 fingerprint (WINDOW_UPDATE, pseudo-header order, stream-3/5 priority weight), a navigation **header-order hash**, `Sec-Fetch-*` rule violations, `Sec-Ch-Ua` vs `User-Agent` coherence, 35 HTTP header features, timing and browser events; classifier reached 97% accuracy. Reported Gemini traces: `headless-chrome` UA family, `HeadlessChrome` in `Sec-Ch-Ua` 100%, `Accept-Language` present 0%, `Sec-Fetch-Site` always `none` 100%. — https://arxiv.org/html/2606.20910v1 (fetched 2026-11-18) — confidence: primary (academic paper). This is evidence Gemini's browser client has detectable fingerprints, not evidence Google performs the detection.
- Same paper: H2 WINDOW_UPDATE and pseudo-header order were identical across all six agents (no discriminative power); stream-5 priority weight (256/220/110) and TLS extension count (16 vs 17) separated some agents. — https://arxiv.org/html/2606.20910v1 (fetched 2026-11-18) — confidence: primary (academic paper).
- OWASP lists Client Hints (`Sec-CH-UA-*`) as a network signal verifiable against TLS fingerprint, and canvas/WebGL/font/audio as stronger but invasive browser-side signals; recommends network-level first. — https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html (fetched 2026-11-18) — confidence: primary (industry guidance).
- Measurement of 10,000 sites: 75% of Chromium-headless-only blocks were caused by header-level signals alone; 46% of sites probed JS properties present only in automated browsers; Cloudflare/Akamai-protected sites had highest block rates (37%/26%). — https://arxiv.org/html/2606.14525v1 (fetched 2026-11-18) — confidence: primary (academic paper). `[inference]` Google-fronted Gemini endpoints sit behind the same general class of edge defenses.

**Google risk scoring, device binding and telemetry**

- reCAPTCHA assessment reason codes published by Google: `AUTOMATION` ("matches behavior of an automated agent"), `UNEXPECTED_ENVIRONMENT`, `TOO_MUCH_TRAFFIC`, `UNEXPECTED_USAGE_PATTERNS`, `LOW_CONFIDENCE_SCORE`; advanced reasons are Enterprise-only. Google does not disclose which low-level signals produce these codes. — https://docs.cloud.google.com/recaptcha/docs/interpret-assessment-website.md.txt (fetched 2026-11-18) — confidence: primary (Google docs).
- reCAPTCHA browser/mobile JS or SDK collects signals in the client and sends them for analysis; session-tokens are refreshed every 30 minutes and action-tokens use client-, server- and action-specific signals. — https://docs.cloud.google.com/recaptcha/docs/features-ca.md.txt ; https://docs.cloud.google.com/recaptcha/docs/overview.md.txt (fetched 2026-11-18) — confidence: primary (Google docs).
- Google's published Android data disclosure states the reCAPTCHA SDK automatically collects IP address, SDK version, package name, user action strings, **device integrity response from Google Play services**, app interactions, some installed apps, and device IDs such as IMEI. — https://docs.cloud.google.com/recaptcha/docs/disclosure-requirements-android.md.txt (fetched 2026-11-18) — confidence: primary (Google docs).
- Google Play Integrity API returns `appIntegrity` (PLAY_RECOGNIZED), `accountDetails` licensing verdict, `deviceIntegrity` (hardware-backed `MEETS_STRONG_INTEGRITY` on Android 13+), `recentDeviceActivity` (high-volume attestation abuse), `deviceRecall` (re-identify previously flagged device after reinstall/reset), `appAccessRiskVerdict`, `playProtectVerdict`; Google states reCAPTCHA Enterprise automatically includes Play Integrity signals. — https://developer.android.com/google/play/integrity/overview (fetched 2026-11-18) — confidence: primary (Google docs).
- Device Bound Session Credentials (DBSC): Chrome generates a device key pair in TPM (Windows) / Secure Enclave (macOS), stores the private key in hardware, short-lived cookies are refreshed only after proof of possession; Google Workspace enables DBSC **on by default for all accounts**, and Context-Aware Access can require DBSC-bound sessions and block unsupported platforms. — https://blog.google/security/protecting-cookies-with-device-bound-session-credentials/ ; https://knowledge.workspace.google.com/admin/security/prevent-cookie-theft-with-session-binding ; https://developer.chrome.com/docs/web-platform/device-bound-session-credentials.md.txt (fetched 2026-11-18) — confidence: primary (Google docs/blog).
- Google explicitly states DBSC is "not ... a device fingerprinting mechanism": per-session keys, no device identifier or attestation data beyond the session public key. — https://blog.google/security/protecting-cookies-with-device-bound-session-credentials/ (fetched 2026-11-18) — confidence: primary (Google blog).
- Gemini CLI (first-party Google source) self-identifies in `User-Agent`: `GeminiCLI/<version>/<model> (os; arch; surface)`, prefixes `GeminiCLI-a2a-server`, `GeminiCLI-acp-zed`, `GeminiCLI-acp-xcode`, `GeminiCLI-acp-intellijidea`, or VS Code form `CloudCodeVSCode/... (aidev_client; os_type=...; host_path=...; proxy_client=geminicli)`; `GEMINI_CLI_SURFACE` sets a custom label; docs say this exists to differentiate Code Assist from standard terminal traffic. Telemetry common attributes include `session.id`, `installation.id`, `user.email`. — https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/telemetry.md ; https://raw.githubusercontent.com/google-gemini/gemini-cli/main/packages/core/src/core/contentGenerator.ts (fetched 2026-11-18) — confidence: primary (first-party Google source). `[inference]` Google's backend can use this header as an official-client signal; no doc states it gates subscription entitlement.
- Cloud Armor bot management can evaluate reCAPTCHA token scores inline at the edge and rate-limit reuse of tokens/exemption cookies; rate-limit keys include `TLS_JA4_FINGERPRINT`. — https://docs.cloud.google.com/armor/docs/bot-management.md.txt ; https://docs.cloud.google.com/armor/docs/rate-limiting-overview.md.txt (last URL fetched via search snippet only, 2026-11-18) — confidence: primary (Google docs) for bot-management/token flow; secondary (search snippet) for the rate-limit key name.

## Conflicting evidence

- Practitioner TLS-fingerprint claim is unconfirmed: issue #323 was closed; commenters proposed ordinary Gemini rate limiting and low IP reputation instead, and no Google statement attributes the 429 to JA3/JA4. Treat as hypothesis, not vendor-confirmed detection.
- Google's own DBSC announcement explicitly says DBSC is designed *not* to be a device fingerprinting mechanism — device binding and fingerprinting must not be conflated.
- Google reCAPTCHA docs publish reason codes (`AUTOMATION`, `UNEXPECTED_ENVIRONMENT`) but no mapping to JA3/JA4, HTTP/2 or canvas signals; "advanced reasons" are withheld behind Enterprise. No public Google document ties any fingerprint signal to Gemini/AI Pro/Ultra subscription enforcement.
- TLS-fingerprint efficacy is bounded: full-stack browser emulation yields identical JA4 to a real browser (Low/None protection), and specialized ClientHello spoofing is rated Medium (arxiv 2602.09606).
- H2 signal discriminative power is bounded: Akamai's own corpus shows Chrome on macOS and Windows share a fingerprint; the 2026 multi-agent study found WINDOW_UPDATE and pseudo-header order identical across all agents, with only stream-5 weight / TLS extension count separating some.
- Cloudflare documents JA3/JA4 as frequently missing (non-TLS, session resumption, Worker-routed, Bot Management skipped) — any detection depending on them needs fallbacks.
- Google-authored 2403.15607 frames browser fingerprinting primarily as a privacy risk to be measured/mitigated, not as a deployed Gemini anti-abuse control.

## Gaps

- No first-party evidence that gemini.google.com or the Gemini mobile apps run JA3/JA4, HTTP/2, canvas/WebGL/font, or device-attestation checks for *subscription entitlement* specifically (as opposed to general anti-abuse/bot scoring).
- No public Google statement on which low-level signals produce reCAPTCHA `AUTOMATION` / `UNEXPECTED_ENVIRONMENT` verdicts.
- No root-cause confirmation for the curl_cffi 429 report; no capture of the actual TLS ClientHello/headers Google rejected.
- No access to closed-source Gemini web/mobile client bundle to enumerate client-side fingerprint collection (canvas, WebGL, audio, fonts) or device-integrity calls.
- Unclear whether Gemini CLI's documented User-Agent surface tags or telemetry IDs are consumed for entitlement decisions vs only for customer GCP logging.
- Full JA4H algorithm detail (parts a–d, header ordering) absent from the current FoxIO spec file; only the author's blog describes the a/b/c/d semantics.
- No primary data on whether Google applies DBSC or Play Integrity to Gemini consumer subscriptions specifically (DBSC is documented for Google Workspace; Play Integrity is documented as a developer API and reCAPTCHA input).
