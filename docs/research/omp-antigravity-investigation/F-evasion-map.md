# F-evasion-map — bypass techniques mapped to omp's built-in `antigravity-cli` path

**Date:** 2026-11-18. Read-only mapping: no source edits, no implementation.

## Scope and anchor

The chosen design is Approach C in `docs/superpowers/specs/2026-11-18-google-ai-subscription-provider-design.md` and the plan in `docs/superpowers/plans/2026-11-18-google-ai-subscription-provider.md`. The extension registers no provider and handles no tokens. The primary provider is built-in `antigravity-cli` (API `antigravity-acp`) driving local `agy acp`; `google-antigravity` is the paused HTTP fallback and `google-gemini-cli` legacy. Reachable hooks are `before_agent_start`, `context`/`input`, `registerTool`/`setActiveTools`, `tool_call`/`tool_result`, and `PI_AGY_PATH`/inherited env before first spawn. See the Pivot addendum below and the Evidence base below; the "header spoofing is impossible" conclusion survives unchanged.

## Pivot addendum (2026-11-18)

Primary provider is now built-in `antigravity-cli` driving local `agy acp`, with `PI_AGY_PATH` as binary/path override. `google-antigravity` is optional direct-OAuth fallback. Core conclusion is unchanged and strengthened: `agy` owns tokens, TLS, headers, and account state; header spoofing is structurally impossible on the CLI path. On `antigravity-cli`, only `before_agent_start` (system prompt) and `context`/`input` (messages) apply; `before_provider_request` and `after_provider_response` do NOT fire because the CLI provider ignores `onPayload`/`onResponse`. Tool shaping is via `registerTool`/`setActiveTools`/`tool_call`/`tool_result`; binary/env via `PI_AGY_PATH` and inherited env before first spawn. `models.yml` headers/baseUrl affect only HTTP fallback providers, never the CLI path. Add speculative S9: content-scrub timing relative to `agy acp` serialization is unverified.
Evidence base (paths relative to this file): [REPORT.md](../google-ai-subscription-blocks/REPORT.md), [F3 fingerprinting](../google-ai-subscription-blocks/findings/F3.md), [F6 token/relay](../google-ai-subscription-blocks/findings/F6.md), [F7 fingerprint/rotation](../google-ai-subscription-blocks/findings/F7.md), [F8 arms race](../google-ai-subscription-blocks/findings/F8.md). Bottoms of those files carry full source URLs; claim numbers below refer to their `## Claims` lists.

Interpretation rules used below:

- **"CLI delegation?"** asks whether the technique survives the boundary where `agy` — not the plugin — builds and sends the HTTP request. `Yes*` = the technique is inherent to delegation, but the plugin is not the actor.
- **Plugin hook vocabulary:** `prompt rewrite` = `before_agent_start`/`context` output shipped to ACP `_meta.antigravity.systemPrompt.append` and ACP input, never argv; `env` = inherited `Bun.env` with only `SSH_TTY=omp-agy-file-auth` and `AGY_CLI_DISABLE_AUTO_UPDATE=1` forced, no per-request injection API; `argv` = fixed `agy acp --agent bridge --gemini-dir … --ide-mcp-port … --dangerously-skip-permissions`, no argv hook; `binary choice` = `PI_AGY_PATH` or managed SHA-512-verified binary; `tool shaping` = `registerTool`/`setActiveTools`/`tool_call`/`tool_result` under `mcp_ide-tools_<name>`; `header spoof` = **not reachable** — `agy` owns sockets/TLS/headers and omp emits no HTTP headers on this path. A TLS MITM gateway would break Google's cert chain and the keyring auth path, so "header spoof" is rejected rather than merely hard.
- **Confidence:** High = vendor doc / first-party source; Medium = first-hand practitioner artifact; Low = inference; Speculative = no source ties the item to consumer-subscription enforcement. No Google document names the signal that drives a consumer ban (REPORT "What would change this"; F8 Gaps).
- **Design non-goal:** the design spec explicitly excludes "changing detection behaviour or evading bans". This file is a feasibility map, not a recommendation to implement anything.

## Feasible

Reachable hooks under the chosen architecture, ranked by how much of the request they actually influence. "Feasible" here means technically reachable from the plugin, **not** that a documented detector is defeated.

1. **Binary choice — use the genuine signed `agy` (and only `agy`).** Highest-value structural move: UA shape, binary signature, header set, TLS/HTTP2 behaviour and keyring auth are then authentically the official client's, with no token handling in the plugin (Matrix 1–2, 20). `PI_AGY_PATH` is a plain env override that skips the managed SHA-512 verification; it is a trust boundary, not an impersonation switch. Confidence: High only that the selected binary is omp's genuine signed CLI process; **Low** for the claim that its upstream header/TLS shape matches the native client — the HTTP request shape is inside the closed `agy` binary and is not derivable from omp source (`F-antigravity-cli-source.md:115`); no traffic capture was performed. Whether any detector scores the shape remains unknown.
2. **Prompt rewrite — harness-marker scrubbing / zero-width scattering.** `before_agent_start` and `context` rewrite the system-prompt blocks and messages omp supplies to the ACP session; the text is not an argv string (Matrix 7). OmniProxy's recorded A/B (raw → `400 prompt_turned_away`, scattered → `200`) is the only direct evidence, and its detector is unknown; the transformation could also alter model behaviour or cache keys. Efficacy for `agy` is Speculative S5; the design non-goal currently excludes it.
3. **Env strip — subscription-lane isolation (not reachable on the built-in path).** No env-strip hook exists on the built-in path: the child inherits `Bun.env` with only the two forced overrides (`SSH_TTY=omp-agy-file-auth`, `AGY_CLI_DISABLE_AUTO_UPDATE=1`), and the seven-key stripping is a historical Approach A idea (`F-antigravity-cli-source.md:52`).
4. **Model selection within the reviewed roster.** Model/effort selection runs through omp's model config and `reasoning`; choosing slugs the subscription is entitled to avoids 400/410 model errors (Matrix 17). No access escalation is possible from the plugin side.
5. **Managed process per account/session.** omp keeps one `agy` process per account/session and restarts it on tools/cwd/credential change; token refresh is owned by omp/agy credential staging and the plugin caches nothing (`F-antigravity-cli-source.md:41`). Reliability benefit, not evasion.

**Not feasible by construction:** header spoof. The plugin never opens a socket to Google; all headers, TLS fingerprints and HTTP/2 frames originate in `agy`. Even an injected `CODE_ASSIST_ENDPOINT` gateway would proxy the CLI's already-built request, not let the plugin rewrite headers, and would move credentials into a third party (see R1). On the built-in path there is likewise no per-request env injection, so this gateway idea belongs to the rejected architecture, not to a reachable hook.

## Speculative

Every item here lacks a Google document or a verified `agy` behaviour; do not implement on the strength of this file alone.

- **S1 — `GEMINI_CLI_SURFACE`/`SURFACE` relabel (Matrix 8).** Env override exists in `gemini-cli` source (F3), but there is no evidence `agy` honours it or that surface labels affect enforcement.
- **S2 — telemetry suppression (Matrix 9).** No documented `agy` telemetry flag; no evidence telemetry affects subscription standing.
- **S3 — proxy/egress env injection (Matrix 15).** "One IP per account" is practitioner advice (F7 §A) and a pinned dispatcher can ignore proxy env entirely (F8 #33); `agy` behaviour unknown.
- **S4 — `CODE_ASSIST_ENDPOINT` injection (Matrix 5).** Technically the strongest env-level hook, but it converts the CLI-delegation architecture into the token-handling relay pattern Google explicitly names as a violation (F6 FAQ; F8 #4–6). High technical confidence, high risk, design non-goal.
- **S5 — prompt-scrub efficacy in the `agy` path (Matrix 7).** OmniProxy's A/B proves its own gateway rejected specific lines; it does not prove a Google detector, nor that `agy` upstream includes those lines. Scattering can also degrade prompts.
- **S6 — "binary signature / UA detector" claim (Matrix 20).** Practitioner speculation (F8 #21); no vendor confirmation. Delegation presents an authentic shape but no measured reduction in bans.
- **S7 — multi-account profiles via CLI flags (Matrix 14).** No `agy` profile-selection argv or env is documented in the design or sources; rotation would require a different architecture.
- **S8 — signal-level attributions generally.** JA3/JA4, H2, header order, IP/egress, hardware ID and OAuth client ID are all `[inference]` in F3/F7/F8. There is no first-party evidence that any token was revoked *because* of bypass use (REPORT open questions; F8 Gaps).

## Rejected

- **R1 — direct HTTP relay to `cloudcode-pa.googleapis.com` / gateway redirection.** Consumer serving on that path ended 2026-06-18; relays report 403/410/429 failures and migrate to Antigravity (F6, F7 §D, F8 #8, #29). Requires token extraction; design approach A rejected.
- **R2 — plugin-side OAuth client impersonation / PKCE token minting.** Requires embedding the published client ID/secret and storing tokens; Google's FAQ names third-party OAuth piggybacking a violation (F6; F8 #4). No plugin-side hook under CLI delegation.
- **R3 — TLS/JA3/JA4, HTTP/2 and header-order spoofing.** Structurally impossible in a CLI subprocess: the child owns the TLS stack and header construction. Not achievable via `prompt rewrite`, `env strip`, `argv`, `binary choice`, or `header spoof` (last one has no socket to touch).
- **R4 — account rotation / quota pooling.** One keyring session per official CLI; no profile-selection hook, and adding one would abandon the "credentials stay in the CLI" property.
- **R5 — web-cookie keepalive, anti-detect browsers, Play Integrity / DBSC.** Those target browser/mobile surfaces; the CLI path has no cookies or browser fingerprint to manipulate.
- **R6 — hooking the built-in Google provider's fetch.** Retired consumer auth/billing path; design approach B rejected.
- **R7 — treating reported time-to-ban figures as detection latency.** F8 #44: published intervals are remediation/cutover windows; practitioner reports are individual observations, not a distribution.
- **R8 — selecting `gemini` as the binary.** Retired consumer endpoint; correct binary choice is the current official `agy`.

**Bottom line:** under the built-in `antigravity-cli` path almost every documented bypass is out of reach because `agy` owns tokens, TLS, headers and account state. The reachable hooks are binary choice (`PI_AGY_PATH` / managed genuine signed binary), prompt/message rewrite (`before_agent_start`/`context`/`input`), tool shaping (`registerTool`/`setActiveTools`/`tool_call`/`tool_result`), and model/effort selection via omp model config; there is no env-strip or argv hook. Header spoofing is impossible with a CLI subprocess because omp opens no socket on this path.
