# F-antigravity-cli-hooks — what an extension can client-shape on the `antigravity-cli` path

Scope: installed omp `18.22.2` at `/home/yuzu/.bun/install/global/node_modules/@oh-my-pi`. Source paths below are relative to that root unless stated. This report is about the built-in `antigravity-cli` provider (`antigravity-acp` API) driving local `agy acp`; the direct OAuth `google-antigravity` CCA provider is a different path. Read-only source study; no code changed.

## Findings

**F1. Of the three named events, `before_agent_start` and `context` fire on the CLI path; `before_provider_request` does not; neither does `after_provider_response`.**

- `before_agent_start` is emitted by session prompt preparation (`pi-coding-agent/src/session/agent-session.ts:9607-9609`) with no provider/api guard. It fires once for an ordinary prompt (`reason: "prompt"`) and once for a parked-subagent revive (`reason: "revive"`, result discarded) — `pi-coding-agent/src/extensibility/extensions/types.ts:1208-1221`.
- `context` runs as `transformContext` on every provider call in the agent loop, before `convertToLlm` and image/provider normalization (`pi-agent-core/src/agent-loop.ts:2007-2019`), wired from `pi-coding-agent/src/sdk.ts:4816-4819,5029`. This includes CLI steps.
- `before_provider_request` is registered and wired generically: `ExtensionAPI.on("before_provider_request", …)` (`types.ts:1917-1920`), `ExtensionRunner.emitBeforeProviderRequest` (`runner.ts:2582-2617`), session `onPayload` (`sdk.ts:4887-4889`), and `streamSimple` passes `onPayload`/`onResponse` into provider options (`pi-ai/src/stream.ts:1875-1876`). But `antigravity-cli.ts` never calls `options.onPayload` or `options.onResponse`: `runStep` uses only `apiKey`, `cwd`, `reasoning`, `signal`, `credentialVersion`, `sessionId`, and `providerSessionState` (`pi-ai/src/providers/antigravity-cli.ts:17-20,48-71`). The hook callback arrives and is ignored.
- `after_provider_response` has no trigger here: the CLI stream returns ACP `PromptResponse` objects through `StepWriter`, not an HTTP `Response` with `status`/`headers`/`requestId` (`types.ts:1203-1206`; `pi-ai/src/providers/antigravity-cli/step-writer.ts:90-117`). **Correction/qualification to F-signature:** its "all chat requests" claim is true for HTTP transports (e.g. `google-gemini-cli.ts` calls `options.onPayload`), not for `antigravity-acp`.

**F2. CCA payload hooks do not apply to `antigravity-cli`.** The CCA-specific seams — `normalizeSchemaForCCA`, `buildAntigravityRequestEnvelope`, `getAntigravityHeaders`, endpoint failover, `labels`, `requestId`, `trajectory_id`, UA/CL values — live in `google-gemini-cli.ts` and are documented for the direct providers in `omp://provider-quirks.md:290-350`. The CLI path is omp → `AgyHost` → ACP JSON-RPC → `agy acp`; `agy` itself builds the CCA request. No extension event exposes that JSON body or its headers. `omp://providers.md` ("Antigravity CLI") states omp supplies only the system prompt and tool schemas, and that inference always runs through the official CLI. Therefore CCA envelope/header imitation is neither reachable nor needed via extension payload hooks on this path.

**F3. Tool shape is the main model-visible seam.** `AgyHost.step` maps `context.tools` through `toMcpTool` (`name`, `description`, `inputSchema` normalized by `normalizeSchemaForMCP`) into a loopback MCP `tools/list` served on an ephemeral IPv4 port (`host.ts:221-249,854-859`; `mcp-bridge.ts:43-100,155-157`). `agy` presents those tools to the model as `mcp_ide-tools_<name>` (`omp://providers.md`; `mcp-bridge.ts:1-4`). Tool execution and approvals remain in omp; the host validates arguments against the advertised schema and returns a schema-aware error on invalid arguments (`host.ts:626-655,883-920`). Tool names/descriptions/schemas therefore are client-shapeable by registering or replacing tools and by changing the active tool set.

**F4. Prompt shape is reachable but has a tool-loop boundary.** `before_agent_start` can return a full `systemPrompt: string[]` replacement; handlers chain in registration order and the override lasts for the next request and its continuations until the next preparation (`types.ts:1785-1789`; `runner.ts:2645-2699`; `session-tools.ts:661-680`). For CLI, the joined system prompt is shipped as `_meta: { antigravity: { systemPrompt: { append: system } } }` on `newSession`/`loadSession` (`host.ts:224-225,267-282,483-500,845-847`). Changing it while a tool turn is parked changes `systemKey`, so `parkedTurnMoves` abandons the live turn and reseeds or restores (`host.ts:227-249`).

**F5. Env and binary path are reachable; argv is effectively fixed.** `PI_AGY_PATH` selects an existing binary and returns early — bypassing download and SHA-512 verification (`pi-ai/src/providers/antigravity-cli/binary.ts:29-34`). The child inherits `Bun.env`; the host then forces `SSH_TTY=omp-agy-file-auth` (headless file-only credential storage) and `AGY_CLI_DISABLE_AUTO_UPDATE=1` (`host.ts:783-802`; `credentials.ts:144-153`). `nc` must be on `PATH` for the IDE-tool bridge (`host.ts:777`). The argv vector is hard-coded: `agy acp --agent bridge --gemini-dir <account dir> --ide-mcp-port <ephemeral> --dangerously-skip-permissions` (`host.ts:42,783-802`). There is no extension API for per-request argv or child env injection; setting `process.env` before first resolution affects later spawns only. `ToolDefinition.shellEnv` applies to user-initiated shell tool invocations, not to the CLI child (`types.ts:1005-1013,1056-1057`).

**F6. Several identifiers are internal contracts, not cosmetic strings.** Renaming them can break the loop even when the model still emits syntactically valid tool calls:

- Built-in tool IDs (`read`, `bash`, `edit`, `write`, `grep`, `glob`, `task`, `wait`, `think`, …) are canonicalized from a fixed list; `think` and `write` are also referenced by host logic (`pi-coding-agent/src/tools/builtin-names.ts:3-33,85-99`; `sdk.ts:4766-4768,5059-5061`). `isToolCallEventType` only specializes the six event-visible names (`types.ts:1674-1687`).
- MCP-discovered tools are minted as `mcp__<server>_<tool>` (`builtin-names.ts:120-123`); do not invent that prefix in prompts.
- `mcp_ide-tools_<name>` is agy's view of an omp tool. `AgyHost` strips that prefix from ACP `tool_call` titles only to announce the tool (`host.ts:48,709-715`); it is not an omp tool name. agy's `manage_task` and MCP resource tools remain internal to agy (`omp://providers.md`).
- Tool call ids (`agy_<uuid>`), the `antigravityCli` provider payload (`conversationId`, `digest`, optional `checkpoint`), and the exact message prefix hashed by `transcriptDigest` must survive context/assistant rewrites; `planTurn` resumes only an exact prefix with the matching pending `toolCallId`, otherwise it restores a checkpoint or reseeds (`host.ts:656-669`; `reconcile.ts:17-83`). Also, `toolsKey = stableStringifyJson(tools)` is compared per step; changing tool definitions while parked triggers abandonment/restart (`host.ts:222-249`).
- Internal URL schemes are host-resolved resources: `omp://` docs, `local://` session-scoped files, `artifact://`, `agent://`, `proc://`, `history://`, `ssh://`, `skill://`, `pr://`/`mr://` annotations (`pi-coding-agent/src/internal-urls/omp-protocol.ts:2-8`, `local-protocol.ts`, `artifact-protocol.ts:2-8`, `agent-protocol.ts:2-19`, `proc-protocol.ts:43-78`, `ssh-protocol.ts`, `extensibility/skills.ts:53-60`, `types.ts:629,811,1036`). Rewriting these to invented schemes in prompts/tool arguments removes the resolver; they are not interchangeable aliases.

**F7. `registerProvider` cannot replace the built-in `antigravity-acp` transport.** Custom APIs are rejected for built-in API ids (`pi-ai/src/api-registry.ts:19-50,72-93`), and `antigravity-acp` is on that reserved list (`api-registry.ts:36`). An extension can register a *different* api id with its own `streamSimple` (`types.ts:2268-2313`; `runner.ts:942-947`; `model-registry.ts:4375-4398`), but then it owns the whole `AssistantMessageEventStream`, credential staging, ACP lifecycle, and tool-loop contract.

## Feasible hooks

1. **Per-turn system prompt rewrite (`before_agent_start`).** Return `{ systemPrompt: string[] }` to replace the whole generated block array; inject or remove harness-marker/identity language before it is joined and appended via ACP `_meta`. Loop-safe only at a turn boundary; keep tool-policy, internal-URL and device guidance if the goal is a working tool loop. Confidence: high.
2. **Prompt/message shaping (`input`, `context`).** `input` can replace interactive text/images (`types.ts:1423-1429,1761-1769`); `context` can add/remove/replace `AgentMessage[]` before provider conversion (`runner.ts:2488-2561`). Preserve tool-call/tool-result pairing, `toolCallId`s, and the exact prefix covered by `antigravityCli` payload digests. Confidence: high.
3. **Tool surface shaping (`registerTool`, `setActiveTools`, description/schema edits).** Add or re-register tools; the name/description/schema are projected to `mcp_ide-tools_<name>` in `agy`'s tools/list. Prefer new names over renaming built-ins; keep names stable for the whole parked turn. Invalid schemas/tools are rejected by the host, not by omp's CCA normalizer. Confidence: high.
4. **Tool-call/result interception (`tool_call`, `tool_result`).** Block or revise arguments, replace result content, and attach trusted `additionalContext` for the next request (`shared-events.ts:345-435`). Revisions are revalidated against the tool schema; do not mutate the `agy_…` id or rewrite a parked result as a different call. Confidence: high.
5. **Visible-output rewrite (`assistant_message`).** Replace finalized assistant `content` only; the event fires before persistence/tool dispatch (`types.ts:1270-1289`). Keep tool-call blocks and `providerPayload` intact. Confidence: medium (streamed text already shown is not retracted).
6. **Binary/env shaping (`PI_AGY_PATH`, process env before first spawn).** Point `PI_AGY_PATH` at the genuine signed `agy`, or at a wrapper that preserves the fixed `acp --agent bridge --gemini-dir … --ide-mcp-port … --dangerously-skip-permissions` + NDJSON ACP/loopback MCP contract. Inherited env can isolate credential lanes; do not expect to override the forced `SSH_TTY`/`AGY_CLI_DISABLE_AUTO_UPDATE`. Confidence: high for mechanics, low for any detection benefit.
7. **Observation hooks (`message_update`, `message_end`, `tool_execution_*`).** Read-only visibility into agy-driven steps and tool execution; useful for verification and for deciding when it is safe to change prompt/tools. Confidence: high.
8. **New provider with custom api id (bounded).** Register a new provider whose `streamSimple` delegates to `streamAntigravityCli`, if a product needs a wrapper around the built-in transport under a non-reserved api name. Must reproduce all stream/payload/tool semantics; no access to CCA internals. Confidence: low/medium (high implementation cost).

## Rejected

- **`before_provider_request` / `after_provider_response` for CLI streams.** The CLI provider ignores `onPayload`/`onResponse`; there is no CCA JSON body or HTTP response metadata to rewrite. These hooks remain useful for HTTP side requests (compaction, direct `google-antigravity`, judges), not for `antigravity-cli` inference.
- **CCA header/UA/envelope/label spoofing from an extension.** `agy` owns the socket, TLS stack, headers and request envelope; extension events only see omp-level prompt/tools/messages. Header spoofing is structurally impossible on this path (consistent with `F-evasion-map.md:56`).
- **Per-request argv injection.** No extension API alters the hard-coded `agy acp` argv; `PI_AGY_PATH` changes which executable receives it. Rewriting `--gemini-dir` in a wrapper would desynchronize credential staging and conversation-store operations.
- **Renaming internal tool names or URL schemes.** Built-in tool IDs, `mcp__` names, `mcp_ide-tools_` prefixes, `agy_…` call ids and `omp://`/`local://`/`artifact://`/`agent://`/`proc://`/`skill://`/`ssh://`/`pr://` schemes are dispatch contracts. agy-internal `manage_task`/resource tools are not omp tools and cannot be renamed from an extension.
- **Registering `antigravity-acp` as a custom API to override dispatch.** Built-in API names are reserved; the registration throws.
- **Passing an access token via `--api-key` or a copied CCA credential.** `omp://providers.md` explicitly warns against this; the transport expects the staged structured OAuth credential in the account-scoped native credential file.
- **Treating a path override as authenticity.** `PI_AGY_PATH` skips the managed download/SHA-512 verification; a shim removes the "genuine CLI" fingerprint that is the main structural advantage of this provider.

## Open questions

- Q1. Does `agy` honour any transport/env knobs outside this repo (e.g. `CODE_ASSIST_ENDPOINT`, `SURFACE`/`GEMINI_CLI_SURFACE`, telemetry switches)? `F-evasion-map.md:61-68` marks these speculative; no installed-omp source confirms them.
- Q2. What measurable detector signal, if any, is affected by prompt-only scrubbing on the CLI path? This report establishes reachability, not efficacy.
- Q3. Does changing the system prompt mid-parked-tool always force a fresh/restore reseed, or can `loadSession` preserve the parked turn in some cases? Source shows a conservative abandonment path (`host.ts:227-249`) but no end-to-end test was run.
- Q4. Can an extension safely re-register a built-in tool name with a new description while keeping the canonical ID, across `--tools` allowlists and approval caches? F-signature asserts yes; this slice did not verify it.
- Q5. Do image-generation, quota and usage side requests ever run through `antigravity-cli`/`antigravity-acp`, or only through HTTP providers where `before_provider_request` fires? Relevant to F-signature O1.
- Q6. If a wrapper is used, which ACP/MCP timing contracts (2s announcement, 165s hold, 180s MCP deadline) must be preserved to avoid silent tool-loop detachment?
