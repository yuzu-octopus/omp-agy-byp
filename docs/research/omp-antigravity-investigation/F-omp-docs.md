# F-omp-docs — omp built-in Google / Antigravity provider (docs-only)

Scope: read-only investigation of omp's published docs from the installed 18.22.2 host (2026-11-18). No repository source was edited. 'High' below means high confidence in what the docs assert; claims corroborated in installed source are cross-referenced to `F-antigravity-cli-source.md` / `F-source-google-addendum.md`.

## Findings

### 1. Provider identity and registration

- There are three distinct Google model-provider namespaces. `google` is the Gemini API-key provider (`GEMINI_API_KEY`); `google-vertex` uses `GOOGLE_CLOUD_API_KEY` or ADC; `google-gemini-cli` and `google-antigravity` are separate OAuth-backed provider IDs. Disabling `google` does **not** disable the other two — each ID must be disabled individually. (`omp://providers.md`; `omp://models.md`)
- `google-gemini-cli` and `google-antigravity` are listed explicitly among OAuth-backed providers normally reached through `/login` rather than an environment variable. Neither has a documented env-credential variable. (`omp://providers.md`)
- `antigravity-cli` is a **different** provider: it runs Google's `agy acp` locally, is logged in with `/login antigravity-cli`, downloads `agy` from Google release manifests with SHA-512 verification into `~/.omp/antigravity-cli/bin`, honours `PI_AGY_PATH`, needs `nc` on `PATH` for its IDE-tool transport, and exports the resulting OAuth grant into omp's credential store. Docs explicitly warn not to copy an access token into `--api-key` for this transport. `providers.md` calls `google-antigravity` "the paused direct-OAuth provider", i.e. distinct from the CLI path. (`omp://providers.md`)
- Built-in providers are declared in two halves: a catalog half (`packages/catalog/src/compat/rules/providers/<id>.kdl`: default model, env fallbacks, seed models, compat rules; runtime discovery factories in `MODEL_MANAGER_FACTORIES`) and an auth half (`packages/catalog/src/compat/rules/auth/<id>.kdl`, compiled by `packages/ai/src/registry/build.ts` into a `ProviderDefinition`). Wire dispatch keys on `model.api`, not just `model.provider`. (`omp://adding-a-provider.md`)
- For these two providers: catalog rows are `providers/google-gemini-cli.kdl` (default model `gemini-3.1-pro-preview`) and `providers/google-antigravity.kdl` (default model `gemini-3.1-pro`); auth policies are `auth/google-gemini-cli.kdl` and `auth/google-antigravity.kdl`. The shared execution engine is `packages/ai/src/providers/google-gemini-cli.ts`; OAuth/project/onboarding hooks live in `registry/oauth/google-gemini-cli.ts` and `google-antigravity.ts`; quota/ranking in `usage/gemini.ts` and `usage/google-antigravity.ts`; catalog discovery in `discovery/antigravity.ts`. Both are described as the Google Cloud Code Assist (CCA) transport wrapper. (`omp://provider-quirks.md`)
- `google-antigravity` is **paused by default** in its auth rules "because using them puts accounts at risk". A paused provider offers no login, refuses token refresh and requests, and ignores stored and environment credentials. `auth.unpausedProviders: [google-antigravity]` re-enables it; only the global config, `--config` files, and runtime overrides count — a project `.omp/config.yml` cannot unpause it. The change applies live in a running session; an auth-broker host must also set it because the broker drops paused credentials. (`omp://settings.md`; `omp://providers.md`)

### 2. Authentication and login paths

- Logins are provider-scoped. Interactive `/login <provider>` / `omp login <provider>` runs the registered flow and saves to the active auth store (default `~/.omp/agent/agent.db`) or the shared broker; a successful login refreshes that provider's model catalog. (`omp://providers.md`)
- Credential precedence (first match wins): runtime `--api-key` → `models.yml` config `apiKey` → stored OAuth → login-saved API key → extension config fallback → provider env var/`.env` → other stored API key. `disabledProviders` is checked **before** credentials. (`omp://providers.md`)
- CCA credentials are stored as JSON `{ token, projectId, refreshToken, expiresAt, email }`. `AuthStorage` is the sole refresh authority; `shouldRefreshGeminiCliCredentials` applies a 60-second skew (`ANTIGRAVITY_REFRESH_SKEW_MS` / `GOOGLE_GEMINI_REFRESH_SKEW_MS`), and stale tokens fail fast before any HTTP request. (`omp://provider-quirks.md`)
- OAuth installed-app flow: callback port **8085** with `/oauth2callback` for `google-gemini-cli`, port **51121** with `/oauth-callback` for `google-antigravity`; paste-code flow is supported (`pasteCodeFlow: true`). Authorization goes through `accounts.google.com/o/oauth2/v2/auth`; `google-antigravity` sends S256 PKCE like the native client. Antigravity scopes: `cloud-platform`, `userinfo.email`, `userinfo.profile`, `cclog`, `experimentsandconfigs`, `aicode`. (`omp://provider-quirks.md`)
- Project discovery / onboarding:
  - `google-gemini-cli`: `POST /v1internal:loadCodeAssist` with a `$GOOGLE_CLOUD_PROJECT` fallback; if no project, `POST /v1internal:onboardUser` with `tierId` of `free-tier`, `legacy-tier`, or `standard-tier`, polling the `LongRunningOperationResponse` up to 24 times at 5-second intervals. Detects VPC-SC restriction via `SECURITY_POLICY_VIOLATED`. (`omp://provider-quirks.md`)
  - `google-antigravity`: mirrors the native `antigravity/hub` flow against `https://daily-cloudcode-pa.googleapis.com`. `loadCodeAssist` carries `{ metadata: { ideType: "ANTIGRAVITY" } }`, repeats with `cloudaicompanionProject` when the response lacks `paidTier`, and refreshes after resolving account state. Accounts without `currentTier` are provisioned once with `onboardUser` and `tierId: "free-tier"`, polled via `GET /v1internal/{operation.name}` every second under one 30-second deadline. (`omp://provider-quirks.md`)
- Broker path: callback ports are derived from the auth registry (`google-gemini-cli:8085`, `google-antigravity:51121`); `omp auth-broker login <provider> --via=user@host` tunnels the callback with `ssh -L` and writes the credential on the remote host. `omp auth-broker import` maps CLIProxyAPI-style JSON `type` values into these provider ids: `antigravity → google-antigravity`, `gemini-cli` and `gemini → google-gemini-cli`. `migrate --from-local` skips local OAuth rows unless `--include-oauth` is set. (`omp://auth-broker-gateway.md`)
- `antigravity-cli` login "exports the resulting OAuth grant into omp's credential store" and uses a private account-scoped native credential file plus a child-only headless-auth environment selecting file storage; docs say not to copy access tokens into `--api-key`. (`omp://providers.md`)

### 3. Endpoints, headers/UA, and client metadata sent upstream

- Wire protocol: CCA posts `POST /v1internal:streamGenerateContent?alt=sse` and consumes SSE. (`omp://provider-quirks.md`; `omp://models.md`)
- Endpoints: `google-gemini-cli` defaults to `https://cloudcode-pa.googleapis.com`. `google-antigravity` auto-fails over between `https://daily-cloudcode-pa.googleapis.com` (primary) and `https://daily-cloudcode-pa.sandbox.googleapis.com` (sandbox), persisting `lastGoodEndpoint` in `AntigravityProviderSessionState`. The catalog generator fixes bundled `baseUrl` to `https://daily-cloudcode-pa.googleapis.com`. (`omp://provider-quirks.md`)
- Header/user-agent contract:
  - `google-gemini-cli` sends `getGeminiCliHeaders()`: `GeminiCLI/0.46.0/<modelId> (platform; arch; terminal)`. (`omp://provider-quirks.md`)
  - `google-antigravity` chat, discovery, quota, onboarding, image, and web-search requests all send `getAntigravityHeaders()`: `getAntigravityUserAgent()` = `antigravity/hub/<version> (aidev_client; os_type=<os>; arch=<arch>; cl=<cl>)`, plus `Accept-Encoding: gzip` and **no explicit `Accept`** to mimic the native Go client (Bun still adds `Accept: */*`). The backend gates newer models (e.g. `gemini-3.7-flash`) on the client version. Platform mapping: macOS `darwin`/`arm64`, Linux `linux`/`amd64`, Windows `windows`/`amd64`; other OSes report the Linux build. (`omp://provider-quirks.md`)
  - Claude 4.x reasoning models on Antigravity send `anthropic-beta: interleaved-thinking-2025-05-14`; Claude 5.x sends none (like the native client) yet still streams interleaved thinking. (`omp://provider-quirks.md`)
- System instructions: Antigravity tags system instructions with `role: "user"`, and **no identity prompt is injected by the client**. (This contrasts with Anthropic's Claude Code OAuth identity injection documented in the same file.) (`omp://provider-quirks.md`)
- Antigravity request envelope (`buildAntigravityRequestEnvelope`) contains `project` (projectId), `requestId` = `agent/<agentId>/<ts>/<trajectoryId>/<step>` with a monotonic `<step>` (1 on first request, 3 after one tool round trip, never decreasing), `userAgent: "antigravity"`, and `labels`: `cascade_id` and `root_cascade_id` (= `agentId`), `last_execution_id`, `last_step_index` (= step − 1), `model_enum`, `request_id` (= `<trajectoryId>-<n>`, 0-based request count), `trajectory_id`, `used_claude`, `used_claude_conservative`, `used_non_gemini_model`. `requestType` is deliberately **omitted**: the official client sends `requestType: "agent"` but omp omits it because it drew false 429 `RESOURCE_EXHAUSTED` errors. Session state holds monotonic `stepIndex`, re…
- Wire profiles: each Antigravity SKU's constants come from the account's `fetchAvailableModels` roster — `model` (`model_enum` label), `maxOutputTokens`, `thinkingLevel` (1/2/3 → `LOW`/`MEDIUM`/`HIGH`), `thinkingBudget` — stored in `Model.antigravityWireProfiles`; `getAntigravityModelWireProfile` falls back to bundled `ANTIGRAVITY_MODEL_WIRE_PROFILES`. The output cap is always sent; Claude 4.6 wire IDs cap `maxOutputTokens` at 64000 because the backend 400s above that. (`omp://provider-quirks.md`)
- Thinking on the wire: Gemini 2.x sends `thinkingConfig.thinkingBudget`, Gemini 3 sends `thinkingConfig.thinkingLevel`. Tier SKUs send the level/budget the SKU advertises (budget `-1` means dynamic); single-SKU effort families keep the effort's own budget. With `thinking.suppressWhenOff`, disabling reasoning emits explicit `includeThoughts: false` plus level/budget. Omitting `thinkingConfig` makes CCA re-apply server defaults and silently bill thinking tokens. (`omp://provider-quirks.md`)
- Tool schemas: `normalizeSchemaForCCA` recursively strips unsupported keywords (`propertyNames`, `additionalProperties`, `patternProperties`, `$schema`, `title`, `description`, …) inside `buildRequest` to prevent CCA HTTP 400s. Tool choice uses `toolConfig.functionCallingConfig` with `mode: AUTO | NONE | ANY` and `allowedFunctionNames`; **Antigravity/Gemini CLI use `mode: VALIDATED` as their default**. (`omp://provider-quirks.md`; `omp://provider-compat-reference.md`)
- Discovery and quota calls that reach the same upstream: `fetchAntigravityDiscoveryModels` posts `{ project }` to `fetchAvailableModels` (or `{}` when no project), as the native client does; usage tracking posts `POST /v1internal:fetchAvailableModels`, bucketed into 24h/7d windows and counter keys `Anthropic`/`Google`/`OpenAI`, with family-based credential ranking (`claude-` → Anthropic, `gemini-`/`gemma-` → Google, `gpt-`/`openai/` → OpenAI). `google-gemini-cli` usage uses `loadCodeAssist` and `retrieveUserQuota` with tiers `3-Flash`, `Flash`, `Pro`. (`omp://provider-quirks.md`)
- Other upstream surfaces: `google-gemini-cli` has an internal SSE image-generation endpoint using the account-advertised image model; web search uses OAuth credentials in `agent.db` for `google-gemini-cli`/`google-antigravity` with a selected `google-*/*` chat model. (`omp://tools/generate_image.md`; `omp://tools/web_search.md`)

### 4. Streaming and response handling

- Chunks deliver `candidates[0].content.parts`, `usageMetadata`, `modelVersion`, `responseId`, `promptFeedback`, or top-level `error`. `chunk.error` with status/code ≥ 400 throws `AIError.GeminiCliApiError` / `AIError.ProviderResponseError`; `promptFeedback.blockReason` throws with `kind: "content-blocked"`. (`omp://provider-quirks.md`)
- Flash models can leak raw JSON internal planning blocks into visible text; `consumePlanningBuffer` strips objects containing `thought`, `call` (matching active tool names), `_i`, `paths`, `command`, or `path`/`content`. Parts with `thought: true` route to thinking blocks; `thoughtSignature` is retained via `retainThoughtSignature`; inline `<thinking>` markup is healed. (`omp://provider-quirks.md`)
- Reliability: `MAX_EMPTY_STREAM_RETRIES = 2` with 500 ms base delay (three total attempts) for empty stop responses; `armPreResponseTimeout` uses `getStreamFirstEventTimeoutMs` with a 5-minute ceiling and disables native Bun fetch pre-response timeout. Gemini CLI owns first-event recovery while the shared forwarding wrapper handles idle gaps. (`omp://provider-quirks.md`; `omp://provider-streaming-internals.md`)
- Unified normalization for Google: `part.functionCall` yields a complete `args` object, emitted as one synthetic `toolcall_delta`; IDs are native or synthesized via `nextToolCallId`; parallel `functionResponse` parts must be merged into one contiguous `user` message. The generic stream contract is `start` → block triplets → `done`/`error`, delivered unthrottled in push order. (`omp://provider-streaming-internals.md`; `omp://provider-compat-reference.md`)
- Endpoint-family constraints that apply here: prefer compat metadata over provider-name branches; keep transport mechanics transport-local; do not emit defaults that alter gateway routing; stop retrying after visible side effects; serialize thinking explicitly because wire fields (budget vs level vs `includeThoughts: false`) are not interchangeable. (`omp://provider-endpoint-constraints.md`)

### 5. Extension override seams

- `pi.registerProvider(name, config)` registers a runtime provider (baseUrl, apiKey, api, models, `fetchDynamicModels`, optional `usage`). Built-in API names are reserved; an extension-owned custom `api` string is legal when `streamSimple` returns a canonical `AssistantMessageEventStream`. Overriding a built-in provider id is allowed and `pi.unregisterProvider(name)` restores the built-in/configured behavior. `registerProvider` with both `oauth` and gateway `apiKey` makes the saved `/login` credential win over the key. (`omp://extensions.md`; `omp://adding-a-provider.md`)
- Extensions register OAuth flows with `registerOAuthProvider` / an `OAuthProviderInterface`; built-in and extension logins share the `AuthStorage.oauth.login` dispatcher. Extension usage providers can override a built-in provider's resolver; set a distinct `cacheVersion` to avoid cross-process cache poisoning. (`omp://adding-a-provider.md`; `omp://extensions.md`)
- `models.yml` user-level seams: provider-level `baseUrl`, `headers`, `apiKey` (env-name-or-literal, `!` command prefix), `authHeader: true`, `compat`, `disableStrictTools`, `requestMetadata`, `modelOverrides`, `discovery`, and `auth: none`; `api: google-gemini-cli` is an accepted API value. `disabledProviders` gates every provider class (bundled, custom, discovered, extension, local). (`omp://providers.md`; `omp://models.md`)
- Session-level fallback routing can swap providers via model-role chains, including a wildcard `google-antigravity/* → google/* → google-vertex/*`. (`omp://settings.md`)
- The pause/unpause seam is config-only and global: `auth.unpausedProviders`. Broker-host config must also include it. (`omp://settings.md`)
- Import seam for third-party credentials: `omp auth-broker import` maps CLIProxyAPI `type` values into `google-antigravity` / `google-gemini-cli` provider ids. (`omp://auth-broker-gateway.md`)

## Open questions

1. Exact OAuth client id/secret and token-exchange/refresh endpoint used by `google-antigravity` — the docs describe the flow and callbacks but not the client credentials or refresh URL.
2. Concrete values/derivation of `<version>` and `<cl>` in `getAntigravityUserAgent()`; docs state the backend gates models on client version but not how `cl` is computed.
3. Contents of `ANTIGRAVITY_MODEL_WIRE_PROFILES` and the full per-SKU `Model.antigravityWireProfiles` schema (docs name the fields but not the model-by-model values).
4. **Pause reason and config-key bypass (resolved).** `omp://settings.md` (Paused providers) and `pi-catalog/src/compat/rules/README.md:424` confirm the operator-layer-only `auth.unpausedProviders` seam; a config `apiKey` does not bypass the pause. See `F-source-google-addendum.md`.
5. Failover thresholds/timing for `lastGoodEndpoint` between the primary and sandbox hosts.
6. Where the signed-decimal `sessionId` is actually serialized on the wire, and whether `agentId`/`trajectoryId` survive process restarts.
7. Exact endpoint URLs and header sets for the Antigravity image and web-search surfaces (docs assert `getAntigravityHeaders()` is used but do not list URLs).
8. Precedence when an extension registers provider id `google-antigravity` (or `google-gemini-cli`) while the built-in is paused — docs cover override generally but not the pause interaction.
9. Whether `PI_AGY_PATH` affects only `antigravity-cli` (docs place it in the CLI section) and which environment selects the "child-only headless-auth" storage.
10. How the broker treats CLIProxyAPI-imported Antigravity credentials when the provider is paused on the broker host.
