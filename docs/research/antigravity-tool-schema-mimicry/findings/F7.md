## Claims

Both fallback providers share one implementation (`pi-ai/src/providers/google-gemini-cli.ts:1-5`), branched by `isAntigravity = model.provider === "google-antigravity"` (`:529`); endpoint choice `:553-589`, `buildRequest(...)` at `:605`, JSON serialization at `:626`. The ACP provider stages credentials and calls `AgyHost.step` (`pi-ai/src/providers/antigravity-cli.ts:55-71`); no HTTP body is assembled. Source: installed paths above. Fetch 2026-11-18. **[PRIMARY]**
- **C2 — CCA tool declarations are caller-shaped at three fields, then schema-normalized.** `convertTools` emits `functionDeclarations: [{ name: tool.name, description: tool.description || "", parameters|parametersJsonSchema }]`; the `parameters` vs `parametersJsonSchema` choice is `model.compat.ccaLegacyParametersSchema` (`pi-ai/src/providers/google-shared.ts:412-435`, esp. `:422,426-431`). For Antigravity, `normalizeAntigravityTools` rewrites every declaration lacking `parameters` into `parameters: normalizeSchemaForCCA(parametersJsonSchema)` (`pi-ai/src/providers/google-gemini-cli.ts:1214-1231`), applied in `buildRequest` at `:1355-1357`. Names/descriptions pass verbatim; only the schema is transformed. Source: installed paths above. Fetch 2026-11-18. **[PRIMARY]**
- **C3 — CCA schema shaping is lossy, so exact target schema/description mimicry is not guaranteed.** `normalizeSchemaForCCA` strips nullable, scalarizes type arrays, merges/collapses combiners, spills stripped human-meaningful keys into `description` (`liftStrippedToDescription: { format: "spill" }`), rejects residual incompatibilities and falls back to `CLOUD_CODE_ASSIST_CLAUDE_FALLBACK_SCHEMA` (`pi-ai/src/utils/schema/normalize.ts:1321-1342`); omp docs list `description` among stripped keywords (`omp://provider-quirks.md:310`) and specify a per-tool fail-open `{ "type": "object", "properties": {} }` fallback (`pi-ai/src/utils/schema/CONSTRAINTS.md:146-166`). - **C4 — Tool-selection mode and forced-tool text are envelope-level controls unique to the CCA path.** `buildRequest` derives `toolConfig.functionCallingConfig` from `options.toolChoice` (`pi-ai/src/providers/google-gemini-cli.ts:1358-1374`; mapping in `pi-ai/src/providers/google-shared.ts:440-450`), defaults Antigravity to mode `VALIDATED` (`:1387-1393`), forces `VALIDATED` for Claude on Antigravity even with no tools (`:1396-1403`), and, for Gemini `mode: "ANY"`, appends the literal directive "TOOL-ONLY TURN. ..." to `contents` because CCA drops `toolConfig` on Gemini routes (`pi-ai/src/providers/google-gemini-cli.ts:1375-1385`; `pi-ai/src/providers/google-antigravity-forced-tool.md:1`). ## Conflicting evidence

- **Path naming:** omp internal docs use `packages/ai/src/providers/google-gemini-cli.ts`; installed 18.22.2 uses `pi-ai/src/providers/google-gemini-cli.ts`. Same implementation (identical function names and line-level content); installed paths are authoritative here.
- **"description stripped" vs `liftStrippedToDescription: spill`:** not a contradiction. `description` is removed from keyword position and its text is spilled into the tool description string (`pi-ai/src/utils/schema/normalize.ts:1331`, `omp://provider-quirks.md:310`), so CCA descriptions are altered, not merely deleted.
- **"Mirrors the real client" vs omitted `requestType`:** the envelope intentionally differs from the official client (`omp://provider-quirks.md:315`); byte-identical mimicry of that field is a known false-429 risk, not a target.
- **`google-gemini-cli` vs `google-antigravity`:** both share `buildRequest`; the Antigravity branch alone adds `normalizeAntigravityTools`, forced `VALIDATED`, directive injection and the envelope (`google-gemini-cli.ts:529,1214-1231,1355-1455`). Do not generalize Antigravity shaping to plain Gemini CLI.
- **Peer angle 2 (F2)** documents that ACP tool-call `name`/`title` are Agent-authored and omp ignores `update.name`; this angle does not claim otherwise — its contrast is that CCA tool declarations are built by omp, while ACP declarations are only projected by omp.
