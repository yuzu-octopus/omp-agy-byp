# F5 — Extension/hook seam reachability on built-in `antigravity-cli` / `antigravity-acp`

## Angle

Which omp extension/hook seams actually run on the built-in Antigravity path in installed 18.22.2, which are structurally dead there, and where a tool-shape adapter + reverse translator must live. Read-only; installed source only. Fetch date for every installed-path source below: **2026-11-18**. Confidence: `primary` = read directly from installed 18.22.2 source; `inference` = primary lines chained; `speculative` = not verified.

Transport shape (anchor for all claims): catalog provider `antigravity-cli` seeds `api="antigravity-acp"`, default model `gemini-4-carbon`; entry header says "Google's Antigravity CLI (`agy acp`) driven as a local subprocess over the Agent Client Protocol" — `pi-catalog/src/compat/rules/providers/antigravity-cli.kdl:1-2,6,17` / primary. Same KDL: `requires-native-tools #true` and "agy executes its control tools internally alongside the IDE MCP tools" (`:9-10`) — primary. Runtime spawns `agy acp --agent <AGENT_NAME> --gemini-dir <dir> --ide-mcp-port <port> --dangerously-skip-permissions` — `pi-ai/src/providers/antigravity-cli/host.ts:783-802` / primary. Host-provided agent def declares `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false` — `pi-ai/src/providers/antigravity-cli/agent.md:1-9` / primary. ⇒ agy-visible tool surface on this path = omp's loopback MCP port only, plus agy-internal control tools omp cannot rename.

## Claims

### A. Tool-surface projection — REACHABLE seam (the adapter location)

- **C1** Tools advertised to agy come exclusively from `context.tools`: `const tools = (context.tools ?? []).map(toMcpTool)` — `pi-ai/src/providers/antigravity-cli/host.ts:222` / primary. `toMcpTool(tool)` = `{ name: tool.name, description: tool.description, inputSchema: normalizeSchemaForMCP(toolWireSchema(tool)) }`; comment: "official CLI owns any provider-specific schema conversion" — `host.ts:854-859` / primary.
- **C2** Normalization is schema-only, not name/description: `toolWireSchema` → draft-2020-12 upgrade (`pi-ai/src/utils/schema/wire.ts:593-608`), then `normalizeSchemaForMCP` (`pi-ai/src/utils/schema/normalize.ts:1345-1364`) strips `nullable`, unsupported fields, keeps names/order — primary.
- **C3** `McpBridge` serves those exact definitions verbatim at `tools/list` (`{ result: { tools } }`) on 127.0.0.1:0; duplicate tool names throw at construction; one connection per process — `pi-ai/src/providers/antigravity-cli/mcp-bridge.ts:43-56,155-157` / primary.
- **C4** agy reports calls back as ACP `tool_call` updates whose `title` matches `\bmcp_ide-tools_(\S+)`; omp strips that prefix to recover the omp tool name — `host.ts:48,709-716`; `mcp-bridge.ts:1-4` / primary. ⇒ tool names agy sees are omp names as advertised; the `mcp_ide-tools_` prefix is added by agy.
- **C5** Extension APIs that feed `context.tools`: `pi.registerTool(ToolDefinition)` with `name`, `description`, `parameters`, `hidden`, `defaultInactive`, `loadMode`, `approval` — `pi-coding-agent/src/extensibility/extensions/types.ts:1015-1048,1969-1970`; `getActiveTools()` / `setActiveTools(names)` — `types.ts:2174-2181` / primary. Active tool names → `tools: initialTools` (`sdk.ts:4898-4900,5015`) → `llmContext.tools = normalizeTools(context.tools, …)` (`pi-agent-core/src/agent-loop.ts:2032-2040`) → `context.tools` in the stream call (`agent-loop.ts:2230-2244`) / inference (primary chain).
- **C6** **Therefore the only extension-reachable point that changes the name/description/schema agy sees is the tool definition/active set itself** (`registerTool` + `setActiveTools`), via `context.tools → toMcpTool → tools/list`. No ACP/MCP-specific hook exists: `McpBridge` is constructed with `options.tools` straight from `host.step` (`host.ts:389-410,781`) / inference (primary chain).
- **C7** Reverse direction: agy `tools/call` → `McpCallHandler` (`mcp-bridge.ts:25-30,158-190`) → `AgyHost.#onToolCall` (`host.ts:626-672`). omp validates args against the advertised schema (`validateJsonSchemaValue`, `host.ts:653-655`), emits `agy_<uuid32>` call id (`host.ts:656`), writes `step.writer.toolCall({type:"toolCall", id, name, arguments})` (`host.ts:665`), computes `transcriptDigest([...step.messages, step.writer.output])` (`host.ts:667`), finishes turn with payload `{type:"antigravityCli", conversationId, digest}` (`host.ts:668`; type `pi-ai/src/types.ts:1245-1259`), then parks and returns the promise (`host.ts:657-671`) / primary.
- **C8** Result path: omp's actual tool execution result is converted by `toMcpOutput(result)` → MCP text/image content + `isError` (`host.ts:861-870`) and returned to the parked `tools/call` (`mcp-bridge.ts:179-190`) / primary. `late-tool-result.md:1-2` shows out-of-band result replay after cancellation — primary.
- **C9** ACP `_meta` is `{ antigravity: { systemPrompt: { append: system } } }` on `session/new` (`host.ts:281,845-847`); `tools/list` call `_meta["antigravity.google/conversation_id"]` is validated as string and forwarded to `onCall` (`mcp-bridge.ts:172-177`; `host.ts:394`) / primary.
- **C10** `toolsKey = stableStringifyJson(tools)`; a changed `toolsKey` (or cwd/credentialVersion) restarts the agy process (`host.ts:223,230-248`); a changed `systemKey` forces conversation reload (`host.ts:224-225,233,254`); `systemKey` change also forces `parkedTurnMoves` recalculation (`host.ts:227-241`) / primary. Any adapter that mutates tool shapes mid-session mutates `toolsKey` → process restart + parked-turn abandonment.
- **C11** agy `requestPermission` callback always returns `outcome:"cancelled"` (`host.ts:821-827`); approvals live in omp's tool loop, not ACP / primary.

### B. Reachable event seams (fire on this path but with limited authority)

- **C12** `before_agent_start` (extensions only; hooks have a reduced variant) fires with `prompt`, `images`, `systemPrompt` and can inject a message and replace the system prompt — `runner.ts:2645-2699`; `types.ts:1208-1221`; hook variant `extensibility/hooks/types.ts:282-293` / primary. On this path system prompt → `_meta` append (`host.ts:281,845-847`) → `systemKey` → reload on change (C10) / inference.
- **C13** `context` fires before each LLM call and can replace **messages only**, not tools: `transformContext = emitContext(messages)` (`sdk.ts:4816-4819`), `ContextEvent { messages: AgentMessage[] }`, deep copy (`extensibility/shared-events.ts:198-210`), applied at `agent-loop.ts:2014-2015` before `convertToLlm`, then those messages become `llmContext.messages` (`agent-loop.ts:2032-2039`) → `host.step` → `planTurn(context.messages, ledger)` (`host.ts:226`) / inference (primary chain). ⇒ reachable for reshaping *replayed* toolCall/toolResult blocks, never the live `tools/list`.
- **C14** `tool_call` / `tool_result` extension events fire from omp's tool loop: `agent.beforeToolCall = #beforeToolCall` (`session/agent-session.ts:2841`), which calls `runner.emitToolCall({toolName, toolCallId, input})` (`agent-session.ts:5902-5950`; `runner.ts:2332-2380`). `tool_call` can **block** or replace `input` + add `additionalContext` (`:5941-5950`); `tool_result` can replace `content`/`details`/`isError` (`runner.ts:2258-2313`) / primary. Hooks have the same pair with narrower result types (`hooks/types.ts:308-411`) / primary.
- **C15** Because agy's call reaches omp first as an assistant `toolCall` block (C7), `tool_call` on this path sees the **agy-chosen tool name and args** at omp dispatch time — i.e. this seam is the natural **reverse translator for arguments/results**, but cannot rename the tool (`toolName` is read-only in both event types) / inference (primary chain).
- **C16** `tool_execution_start/update/end` are `pi-agent-core` stream events pushed by the tool runner (`agent-loop.ts:3524-3570,3620-3650`) and are extension-only (`types.ts:1291-1316`; absent from `hooks/types.ts:396-411`) / primary. They are observational; no rename/replace field.
- **C17** `assistant_message` is extension-only and **can rewrite content**, but runs **after** the agy digest was computed (C7) — `transformAssistantMessage(finalMessage)` at `agent-loop.ts:2385-2390`, wired to `runner.emitAssistantMessage` at `sdk.ts:5100-5124`; docs call it the single source of truth for history/persistence/next request (`types.ts:1270-1289`); `transformAssistantMessagePreservesToolCalls: true` (`sdk.ts:5127`) / primary. Rewriting a toolCall id/name here desynchronizes from the `AntigravityCliPayload.digest` and can force the checkpoint fallback (`host.ts:258,267-276`) / inference.
- **C18** `message_update` / `message_end` fire (StepWriter emits the assistant stream; agent-session queues these to extensions at `agent-session.ts:4127-4131`), but `message_end` is explicitly notification-only — detached snapshot, in-place edits do not rewrite context (`types.ts:1259-1268`); `message_update` text already streamed is not retracted (`types.ts:1270-1284`) / primary. Not a rewrite seam.
- **C19** `input` is interactive/RPC user submission only (`types.ts:1423-1429`), no tool-schema field / primary.
- **C20** `registerProvider(name, config)` can add models/baseUrl/oauth and, with `streamSimple`, delegates to `registerCustomApi(config.api, …)` (`model-registry.ts:4355-4406`); extension surface at `types.ts:2250,2258` / primary.

### C. Structurally unreachable seams on this path

- **C21** `registerCustomApi` **cannot** replace the agy transport: `antigravity-acp` is in `BUILTIN_API_IDS` (`pi-ai/src/api-registry.ts:19-38`, entry at `:36`), `BUILTIN_APIS` set at `:46`, `isBuiltinApi` at `:48-51`, and `assertCustomApiName` throws `ConfigurationError` "built-in API names are reserved" (`:72-76`) before registration (`:81-93`) / primary. `registerProvider` with `api:"antigravity-acp"` + `streamSimple` therefore throws via the same path / inference.
- **C22** `before_provider_request` (extension `onPayload`) and `after_provider_response` (extension `onResponse`) are wired only into stream **options**: `onPayload = emitBeforeProviderRequest`, `onResponse = emitAfterProviderResponse` (`sdk.ts:4887-4892,5024-5025`) → Agent (`pi-agent-core/src/agent.ts:2055-2057`, `setProviderResponseInterceptor` `:1226-1227`) → `agent-loop.ts:2241` → `pi-ai/src/stream.ts:1874-1877` (`beforeDispatch`, `onPayload`, `onResponse`, `onSseEvent` in `base`) / primary.
- **C23** The agy stream **drops those options**: `streamAntigravityCli` builds a narrow `stepOptions = { cwd, reasoning, signal, credentialVersion }` (`pi-ai/src/providers/antigravity-cli.ts:48-71`, exact object `:59-64`) and calls `host.step(model, context, stepOptions, writer)`. `host.step` reads only those fields (`host.ts:221-233`) / primary.
- **C24** Zero references to `onPayload`, `onResponse`, `beforeDispatch`, `onSseEvent`, `emitBeforeProviderRequest`, or `emitAfterProviderResponse` anywhere under `pi-ai/src/providers/antigravity-cli/` (grep, 2026-11-18) / primary. By contrast HTTP providers call them: `google-gemini-cli.ts:606`, `google-shared.ts:1196`, `openai-completions.ts:952`, `openai-responses.ts:880/920`, `anthropic.ts:2338` / primary. ⇒ payload/response hooks **never fire** on `antigravity-acp`; they cannot touch ACP JSON-RPC, the MCP bridge, tool schemas, call ids, or results. Note `AntigravityCliOptions extends StreamOptions` (`antigravity-cli.ts:17-20`) accepts the fields type-wise but does not call them — accepted ≠ invoked / primary.
- **C25** `after_provider_response` carries `{status, headers, requestId, metadata}` (`runner.ts:2633-2639`; `types.ts:1203-1206`) — an HTTP `Response` concept absent from the ACP subprocess transport (`host.ts:821-827` uses NDJSON streams, no HTTP Response) / primary.
- **C26** `registerOAuthProvider` is internal to `ModelRegistry.#registerProvider` (`model-registry.ts:4400-4406`) and not a standalone extension API; antigravity-cli login/refresh are registered as first-party hooks (`pi-ai/src/registry/hooks/custom.ts:16,23`) / primary. Out of scope anyway (no auth work in this angle).
- **C27** `setUnpausedProviders` is a settings effect (`pi-coding-agent/src/config/model-settings.ts:7,92`; `session/auth-broker-config.ts:37,153`), with **zero** occurrences under `pi-coding-agent/src/extensibility/` (grep 2026-11-18) — not an extension seam / primary.
- **C28** `transformProviderContext` is the one internal hook that can rewrite the whole `Context` including `tools` (`agent-loop.ts:2045-2047`), but SDK assigns it only to its own transform chain (`sdk.ts:4884,5030,5469,6195`); no extension registration path found / primary + inference. Not reachable by an extension in 18.22.2.
- **C29** `onSseEvent` / `beforeDispatch` are likewise passed into `base` (`stream.ts:1874,1877`) but have no call site in the agy transport (same grep as C24) / primary.

### D. Named failure modes (all anchored)

- **C30** Duplicate renamed tool names → `McpBridge` constructor throws "Duplicate Antigravity CLI tool name" (`mcp-bridge.ts:52-53`) → transport start fails (`host.ts:781,833-836`).
- **C31** Non-object schema after normalization → `toMcpTool` throws "Invalid schema for Antigravity CLI tool …" (`host.ts:856-857`). MCP-incompatible constructs are stripped by `normalizeSchemaForMCP` (`normalize.ts:1345-1364`), silently changing advertised semantics.
- **C32** Schema/name drift mid-turn → `toolsKey` change → process restart (`host.ts:230-248`); parked tool call is detached (`host.ts:381-387`) and replayed via `lateToolResultPrompt` (`host.ts:298-300`; `late-tool-result.md:1-2`). Adapter must keep `toolsKey` stable for session lifetime.
- **C33** Transcript rewrite vs digest → rewriting toolCall id/name via `assistant_message` or `context` changes `transcriptDigest` inputs (`host.ts:667-669`) without recomputing stored `AntigravityCliPayload.digest`; next step sees divergence and rewinds to newest matching turn end or replays whole transcript as text (`types.ts:1245-1250`; `host.ts:258,267-276`) / inference (primary chain).
- **C34** Approval mismatch → agy-side permission is auto-cancelled (`host.ts:823`); omp approval tiers come from `ToolDefinition.approval` (`types.ts:1038-1043`) and are resolved against the tool name omp dispatches (`agent-session.ts:5917-5924`). Shadow-renamed tools need their own approval policy or approvals attach to the wrong identity / inference.
- **C35** Unknown agy tool name → MCP `tools/call` returns `-32602 Unknown tool` (`mcp-bridge.ts:158-166`), and `#onToolCall` rejects calls outside active step/conversation (`host.ts:638-652`). Renames must be applied at registration, not by intercepting `tools/call`.
- **C36** Version drift: agy binary is auto-updated but pinned off (`AGY_CLI_DISABLE_AUTO_UPDATE=1`, `host.ts:800`); catalog notes are for `agy acp` 1.5.9 (`antigravity-cli.kdl:12-16`). Official tool identity beyond this bridge unverified (see Gaps).

### E. Recommended seam (answer form)

- **C37** Put the **tool-shape adapter at `registerTool` + `setActiveTools`** (C1-C6): register Antigravity-shaped shadow tools (name/description/parameters) and deactivate canonical originals; their `execute` maps back to canonical omp behavior. Put the **reverse translator in `tool_call`/`tool_result` handlers** (C14-C15) for argument/content normalization, or inside the shadow tool's execute (same place, no double translation). Keep `context`/`assistant_message` rewrites out of toolCall ids/names to preserve digests (C33). Do **not** attempt `onPayload`/`onResponse` or `registerCustomApi` on this path (C21-C25) — they are dead ends; those seams exist only for the direct HTTP CCA fallback / inference (primary chain), to be contrasted by the CCA agent.
- **C38** Feasibility matrix (all `primary`/`inference` per above): `registerTool`/`setActiveTools` = REACHABLE, authoritative for agy-visible tool shape; `context` = REACHABLE, messages only; `before_agent_start` = REACHABLE, systemPrompt/message only; `tool_call`/`tool_result` = REACHABLE, args/results only; `tool_execution_*` = REACHABLE, observational; `assistant_message` = REACHABLE but digest hazard; `message_update`/`message_end` = REACHABLE but non-authoritative; `input` = REACHABLE, irrelevant; `registerProvider` = REACHABLE for new providers, blocked for built-in API id; `before_provider_request`/`onPayload` = UNREACHABLE; `after_provider_response`/`onResponse` = UNREACHABLE; `beforeDispatch`/`onSseEvent` = UNREACHABLE; `registerCustomApi("antigravity-acp")` = BLOCKED (throws); `registerOAuthProvider` = internal only; `setUnpausedProviders` = not an extension seam; `transformProviderContext` = internal only.

## Conflicting evidence

- `BUILTIN_API_IDS` comment calls built-ins "request adapters built into stream dispatch" (`api-registry.ts:48`) while `antigravity-acp` is a subprocess transport (`antigravity-cli.kdl:1-2`). Resolution: both agree it is reserved and not extension-replaceable; the comment is generic wording, not a claim of HTTP dispatch.
- `AntigravityCliOptions extends StreamOptions` (`antigravity-cli.ts:17-20`) suggests payload/response hooks are supported; runtime proves they are not invoked (C22-C24). Type acceptance is not runtime reachability.
- `agent.md` declares `tools: []` / `excludeDefaultComponents: true` while `antigravity-cli.kdl:9-10` says agy runs internal control tools. Not contradictory: omp controls only the IDE-MCP surface; agy-internal tools are outside omp's reach.
