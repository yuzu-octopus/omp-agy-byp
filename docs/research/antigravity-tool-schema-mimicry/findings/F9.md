## MCP spec verification

Fetched 2026-11-18.

- `https://modelcontextprotocol.io/specification/2025-06-18/server/tools` — RESOLVES yes (reader used markdown alternate `.../server/tools.md`), title "# Tools". Data Types → Tool: **`name`** is the unique identifier for the tool ("intended for programmatic or logical use"; schema says `name: string`, required); **`title`** optional display name; **`description`** optional human-readable description, described as a "hint" to the model; **`inputSchema`** is a required JSON Schema object `{ type: "object", properties?: {[key:string]:object}, required?: string[] }` defining expected parameters; `outputSchema` and `annotations` are optional; `_meta?: {[key:string]:unknown}` is present on Tool. `tools/list` returns `{tools: [...], nextCursor?}`; servers supporting tools MUST declare the `tools` capability (`listChanged` optional); invocation is `tools/call` with `name` + `arguments`. Tool annotations are all untrusted hints. [P]
- `https://modelcontextprotocol.io/specification/2025-06-18/schema` — RESOLVES yes (alternate `schema.md`), "# Schema Reference". `Tool` interface confirms the field set above (schema.md lines 798-820) and that `_meta` on Tool is `{ [key: string]: unknown }`; `ListToolsResult` and `Request.params._meta` (with reserved `progressToken`) are also defined. [P]
- `https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/meta` — RESOLVES **no**, HTTP 404. The canonical `_meta` rules are at the linked `https://modelcontextprotocol.io/specification/2025-06-18/basic/index` (alternate `basic/index.md`, "# Overview", §General fields → `_meta`), which RESOLVES yes. [P]
- `_meta` constraints from `basic/index#meta` (fetched 2026-11-18): reserved by MCP for clients/servers to attach additional metadata; certain key names are reserved for protocol-level metadata and implementations MUST NOT make assumptions about values at those keys; valid keys have an optional **prefix** plus a **name**; a prefix is dot-separated labels followed by `/`, labels start with a letter and end with letter/digit with letters/digits/hyphens inside; any prefix containing `modelcontextprotocol` or `mcp` as a label is reserved (examples `modelcontextprotocol.io/`, `mcp.dev/`, `api.modelcontextprotocol.org/`, `tools.mcp.com/`); a non-empty name must begin and end alphanumeric and may contain `-`, `_`, `.`, alphanumerics. Consequence for the research: an omp/agy `_meta` key such as `antigravity.google/conversation_id` or a vendor `antigravity` object is syntactically legal MCP metadata (prefix `antigravity.google/`, name `conversation_id`), but MCP itself assigns it no semantics and neither ACP nor MCP guarantees a peer reads it. [P / consequence I]
- Version note: ACP's extensibility page links MCP's **2026-07-28** `basic/index`, while omp's loopback bridge advertises protocol `2025-06-18`; the `_meta` key-format rules above are taken from the 2025-06-18 page matching omp's advertised version. [P]
